## 根因与新增反例

### 1. 完整地图结算重入：真正影响产品的执行缺陷

正常Node栈可复现：D1 08:00只有一个move→warehouse意图，due495；`advanceWorld(495)`后时钟516，同一intent留下22条workLog，最终rejected，但人已经到仓库。根因是结算同步调用原图travel，travel又推进世界，重新认领仍为working的同一intent。

修正必须统一时钟和结算认领；不能只去重日志或把拒绝改成功。原图行走要有可恢复阶段或在唯一调度器里支付真实工时，物理提交不能再次推进整套时钟。精确复现、源代码位置与正常栈stdout见 `runtime/REPORT.md`、`runtime/fullmap-normal-stack.json`。

### 2. 记忆预算首条例外，及新旧执行权限分叉

首条长承诺在budget64下被当前计数器记为6580，19748字节实际进入renderer；`chosen.length > 0`使第一条绕过硬预算。需显式截断/证据指针，保留来源、时间、撤销状态和截断标记，并准确区分估算单位与tokenizer实测。

正确地点下，R8外层拒绝即时采集，但底层`session.executeCandidate`不传grant仍0分钟采木30→33。标准runStep已归队；这是可达兼容API分叉，本轮未构造用户输入让旧planner恰选采集的完整产品漏洞。新profile需统一权限，legacy能力明确隔离。

primary为223全接受/70空集/19区分；实际隔条编码156案，其中base训练91案只有8个区分题，discharge训练只有6个。base的dev39只有4区分、test26只有3区分，新旧头test均26/26；四头dev指标舍入后并列，warm17由tie-break选出。修改比较精度不能代替更有信息的任务。

所有312案都先等首动作完成、再续跑120分钟，候选终局绝对时钟不同，观察时长120–180分钟。这可以描述动作后延续结果，不能解释为同一承诺deadline前的公平比较。应从共同t0设共同deadline，长动作的时间就在此窗口内计费。

### 4. manifest是双入口契约，不是完全没有身份绑定

真实loader元数据复跑显示：交付schema与服务匹配；服务只认`reference-imitation`，不认诚实的`same-snapshot-branch-rollout`。H因此省略manifest参数，但外层确实逐回复校验headSHA/featureIdentityHash/rendererId。这不是无绑定，更不是伪造实模。

问题是网页/普通CLI不能继承H的特殊校验，服务返回manifestSha=null，违背统一线上契约。必须由共享validator支持真实标签来源，再实际传入manifest；仅加参数会失败，伪改标签来源也不成立。历史四局保持“外层绑定的诊断实模”，不能事后补证成新的完整准入实验。

- `/1`旧头不能进`/2`；当前是新头×两记忆，而不是旧/新×两记忆。应在同`/2`输入与特征上重训旧配方基线，明确这是配方比较，不冒充原R9头直接迁移。
