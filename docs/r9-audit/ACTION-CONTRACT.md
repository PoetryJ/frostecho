# 持久行动契约：给O/A的算法边界

沿用现有World、TaskBoard、CommitmentBoard、runStep和已提交回执；不另建一套任务系统。R9把即时动作改为延迟工作后，应将其视为可中断的持久执行，而不是保存一个稍后调用的闭包。

每个ActionIntent至少持久保存：actionId/commandId、actorId、原始候选与输入身份、generation/授权令牌、taskId、commitmentId与revision（若有）、start/due、地点前提、资源需求、status、最终receiptIds与失败原因。没有taskId的自主行动仍合法，不能强行归给同类任务。

## 开始与结算

开始：在唯一权威入口检查存活、占用、地点、参数、已知授权与命令幂等；登记working，不提前产资源/履约。所需条件变化不能只影响候选层，直接命令与结算也须验证。旧profile兼容保留，新profile不得绕回即时底层路径。

推进时钟：下一时点取目标时刻、规则事件和所有未完成due中的最小值；按既有规则推进所有居民/炉/机器到该点，然后按固定且保存的顺序结算到期动作，再处理由结果产生的新事件。每次使用当前权威时刻重算，防止结算中的移动/危机嵌套推进导致外层时间倒退。相同时间的先后策略必须明确，不能依赖Map插入顺序的偶然差异。

结算：从持久描述复核generation、义务实例/revision/终态、地点、资源与存活。失效→写取消/失败的终态记录，零新增物理效果；有效→恰好一次权威提交，登记receipt，再将同一回执投影到准确task/commitment。receipt已提交而投影尚未完成时重启，重放确定性投影即可，不能再次执行物理动作。

取消：已提交的不可逆效果保留；尚未提交的效果撤销。超时、显式取消、改约和死亡分别有原因。主动生产、已同意义务与NPC个人信念不是同一概念：世界可以撤回授权，但未听见的NPC输入不能因此出现unheard-cancellation之类隐藏标签；实际收到的拒绝回执随后可以成为新的个人观察。

恢复：只重建数据与确定性投影，不依赖settleHooks。对同一待完成ActionIntent，在连续进程与新进程中推进后，比较全部权威状态、义务关联、待完成队列、终态与回执，不能只比时钟或保存文件大小。

资源：共同CPU基线先保留明确的“完成时仲裁”语义，记录实际失败，避免修复时悄悄改经济。若选“开始预留、取消释放”，必须有独立账本、负控和对照，并重采数据；候选mask本身不能预留最后一份食物。任务地点规则应只有一份数据，候选、直接权威动作和settle共用。

## 反馈与训练

每个decision→ActionIntent→terminal outcome保持关联。queued/working/busy不是applied；最终applied/rejected/cancelled/missed-deadline/unresolved分别统计。单步摘要、四日摘要与workLog重算必须一致。模型下一请求接收自己的真实反馈。

记忆投影只有一处：所有入口使用同一memoryPolicy实现。传输结构有source不代表渲染文本有source；在encoder前验证字节和token预算。active义务、最新亲见证据、推断依赖分层保存；笔记失效只撤推断，不删除原始记录。

训练先使用实际模型访问的状态；从同一快照执行各候选并继续固定时段，保留真实回执、剩余资源与义务结果。危险/越权候选先按约束排除，其余允许多条合理路线。候选全可接受的题可以作为权限正控，不能主导选头；必须同时报告随机与简单规则基线。dev、test按源episode及其分支隔离，test只作最终评价。

无效循环的判据至少涉及同一义务/修订、相关证据不变、无可解释的回执进展与代价；连续采集能完成数量目标时应保留。禁止仅凭actionId重复N次加硬惩罚。模型如果长期偏采食，先看是否已看到供暖缺口、真实义务、due与机会成本，再比较短程/长程训练目标。

## 一次集成必过的最小语义矩阵

并行rest正控；工作中cancel；工作中save→新进程；精确第二任务实例；非整点due与不同分块；错地点直接命令与settle；多人争最后资源；听见/未听见取消的输入非干扰；规则/模型错误后真实反馈。每项有成功与失败两侧，不把“所有动作都拒绝”算修好。

将这份矩阵在CLI、网页HTTP和四日runner至少各走一条组合故事。完成共同CPU契约后再训练，不在当前冻结R9原始数据上回填成功。
