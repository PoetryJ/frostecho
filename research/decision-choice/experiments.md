# 两个独立候选实验（均未授权，authorizedCalls = 0）

两个实验**必须分开执行、分开记账**，不得在同一次调用里同时改候选顺序和解码/输出约束，
否则任何一个差异都无法归因。两者都**不占 8 次玩法额度**（研究另立账本），
且都**不得**修改生产 prompt 模板、候选集、thinking 或采样参数。

---

## 实验 1：位置对照（order swap）

- **假设**：在同一上下文里交换 `candidateGoals` 顺序，模型给出的 goal 会改变（至少一个上下文）。
- **自变量**：候选顺序（正序 / 反序），2 水平，**组内**配对。
- **因变量**（只此两者）：
  1. 格式合法率：是否只返回一个合法 JSON 对象且 `goal` ∈ 候选集；
  2. 位置稳定性：同上下文两次答案是否一致；若不一致，记录偏向（首项/末项）。
- **设计**：`candidates.md` 的 4 个上下文 × 2 个顺序 × 1 rep = **8 次**（`proposedCalls=8`）。
  2 对正序先、2 对反序先（counterbalanced），避免"第一次总是正序"引入的顺序惯性。
- **判定**：
  - 全部 8 次格式合法 且 4 个上下文各自两序一致 → "在本次 4 个上下文上未观察到顺序依赖"（**不是**"无偏置"）；
  - 任一上下文两序不一致 → 记录该上下文与两个答案，报告"该上下文的单次结果带顺序依赖"；
  - 任一格式非法 → 归入实验 2 的问题域，本实验只记录不计入稳定性。
- **样本量警告**：n=1/单元，**不能**做统计推断；结论只能写成"出现了/未出现"。
- **失败即停**：任一调用 5xx、超时或 usage 缺失，立即停止，不重试不补测；已花调用如实记账。

---

## 实验 2：输出约束（纯格式，不动候选与解码）

- **假设**：在不改候选顺序、不改 thinking/采样的前提下，输出约束会影响**格式合法率**。
- **自变量**：输出约束，2 臂：
  - A 臂：现行模板（"只回复一个 JSON 对象，不要输出任何其他内容"，`src/negotiation/contracts.ts:228`）；
  - B 臂：现行模板 + 一行"如需说明，请在 JSON 之后另起一行，以 `#` 开头"（仅放宽**说明文本**的位置，
    仍要求首个 JSON 对象合法）。
- **因变量**：仅**格式合法率**（首个 JSON 对象是否可被 `src/agent/parser.ts` 的严格解析接受）。
  正确率/性能**不在**本实验范围。
- **设计**：4 个上下文 × 2 臂 × 1 rep = **8 次**（`proposedCalls=8`），候选顺序固定为正序（消除实验 1 的因子）。
- **判定**：两臂合法率不同 → 输出约束影响格式；相同 → 本样本下无可观察差异。
- **风险**：B 臂放宽说明后，模型可能把 JSON 写进说明里，反而降低合法率——这正是要测的。
- **成本**：与实验 1 合计 16 次研究调用，**必须**先取得单独授权与研究账本。

---

## 两个实验共同的硬边界

1. `authorizedCalls = 0`：本文档不发起调用，只是设计。
2. 不占玩法额度（8 次/每场 4 次），不写 `artifacts/g11-live/**`。
3. 不重启服务、不改模型名、不改 `temperature/max_tokens/stream/enable_thinking`。
4. 失败即停，不重试、不补测、不"再跑一次看看"。
5. 结论只能写"格式合法率"与"位置稳定性"；性能/正确率标注"需后来实测"。
