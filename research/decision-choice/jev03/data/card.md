# JEV-03 数据卡

生成 2026-11-10。全部为 `synthetic_dialogue`：由编码代理撰写，不是真人语料，也不是人工标注。

## 1. 结构与规模

| split | 例数 | 来源组 | 每组 | 每类 | 不同玩家原文 |
| --- | --- | --- | --- | --- | --- |
| train | 384 | 48 | 8（每类 2） | 96 | 384 (100%) |
| dev | 128 | 16 | 8 | 32 | 128 (100%) |
| test | 256 | 32 | 8 | 64 | 256 (100%) |

- 96 个场景组互不重叠，场景名也不同；组 ID 不跨 split；train/dev/test 之间玩家原文零交集，
  且与冻结的 JEV-01/02/R1 语料零重合（`data/build.py` 硬门控）。
- 每组固定 8 个语义句型（8 basic：PF1/PF2/NF1/NF2/NO1/NO2/NC1/NC2）。
  **test 有 13 个场景组改用 4 个困难变体/类**（PF3 条件式自称先、PF4 先转述再表态、
  NF3「给我留点，你先吃」、NF4 带理由让先；NO3 纯复述过去、NO4 多人在场无先后词；
  NC3 转述当下他人意见、NC4 条件/指代不唯一），其余 19 组用基础句型；
  按类统计的变体分布为 19/19/13/13。
- dev 只用 8 个基础句型：选 epoch/seed 的分布比 test 简单，这是已披露的局限，不做事后修正。

## 2. 语义合同

`contract.json` 为 semantic-contract/2（工人 A 会话产出，写入数据前冻结）：
13 条规则 + 与 R1 的逐条差异。关键修订：

- R3/R6 冲突澄清：**没有当前先后安排 → NO**，在场人数本身不是澄清理由；
  有先后请求但收话人/方向/必要条件不唯一 → **NC**；「标注者或模型没把握」不是 NC 的理由。
- R6：纯复述过去 → NO；转述**当下**他人意见且「转述=认可」两读 → 进 challenge，不强裁。
- R7：省略主语但收话人唯一 → NPC；不得补入上下文未出现的长幼/主客规矩。
- R10：多人在场且整句无先后词（如两份饭「趁热吃，都热着」）→ NO。
- R5：「给我留点，你先吃」→ NPC；单纯留份不是优先权请求。

`boundary.jsonl` 是 32 条公开边界样例（含 8 条「多人在场但判 NO」、4 条纯复述、
4 条引用他人意见、3 条多收话人判 NC）。

## 3. 标注与盲测

1. 作者标签：主 agent 依据冻结合同逐条写入 `labelId/rule/reason/move`。
2. 独立盲标：五个独立会话（A1/A2/A3 标 train/dev，D1/D2 标 test），只给合同第 3 节与
   打乱后的无标签输入，不给标签、组名、split 归属；互不通信。原始紧凑编码与映射保存在
   `blind/labels.json`（含会话名），完整文本保存在 `blind/*.jsonl`。
3. 一致率：train 360/384 = **93.75%**，dev 112/128 = **87.50%**，test 184/256 = **71.88%**。
4. 分歧 112 条：102 条依据冻结规则维持作者标签（逐条记 `data/adjudication.json`，附规则号），
   10 条判为两种读法都成立并进入 `challenge.jsonl`（全部是 NC3 转述当下意见），不计入主准确率。
5. 最大争议簇：NC2「都行/再说/还没定」——合同 R8 明确列为 NC，盲标方多按 R3 判 NO（约 50 例）。
   **本轮按冻结标签计分，不事后改标签**，并在报告里给出该规则争议的说明。

**独立性边界**：盲标与作者是同一模型的不同会话，属同源弱监督；一致率为 71.9%–93.8%，
不能当作标签正确性的证据，也不是人工复核。

## 4. 封存

- `test.gold.json`：自校验 SHA + 逐条 `{labelId, groupId}`，只在 `unseal.py` 里读一次。
- test 输入只有 `caseId/groupId/visibleInput`，`scene/move/labelId/rule` 一律不进入 prompt；
  caseId 为不透明序号。
- 预测前封存：`results/selection-seal.json`（两个选定头的 tensor SHA、数据/合同/gold 哈希、
  比较规则）。预测进程内对 gold 的打开会被 `GoldSeal` 拒绝并计数（正向对照见 `unseal-record.json`）。

## 5. 已知局限

1. 合成数据、单一作者；96 个「来源组」是写作场景，不是独立采集来源。
2. 8 个句型在每组重复出现，**表面线索可以直接区分标签**；高分不证明语义理解，
   这也是本轮所有臂都接近天花板的原因之一。
3. test 的困难变体在 dev 中不出现，选 epoch 略偏简单分布。
4. challenge 10 例被排除在主分母之外；包含它们的版本在报告 §8 给出，以免高估。
