所有条目均为 `synthetic_dialogue`：**由编码代理撰写，不是真人数据，也不是人工标注**。

## 2. 语义合同

`contract.json` 在写数据前冻结，规则 R0–R9 + 3 条公开回归。要点：

- 只判定当前玩家向明确收话人表达的优先请求，不裁判多人冲突，不替 NPC 决定服从。
- 收话人明确时“先吃吧”= NPC_FIRST，不因省略主语判澄清（R7）。
- 留饭/打包本身不是优先权请求（R5）。
- 转述他人意见≠本人请求；只转述而无本人请求 → 澄清（R6）。
- 出现优先权字样但收话人、方向或指代无法唯一确定 → 澄清（R1/R8）。

## 3. 标注过程与独立性（如实说明）

1. **作者标签**：主代理（单一作者）按合同逐条撰写 `context + playerText + labelId + reason + provenance.rule`。
2. **独立盲标**：4 个独立代理会话，各自只拿到 `contract.json` 与打乱后的无标签输入（caseId/context/playerText），
   不提供标签、理由、族名、切分归属；会话间不通信。产出 `blind/labels-1..4.jsonl`（512 条全覆盖）。
3. **一致率**：507/512 = **99.0%**（cal-temp 99.2%，cal-policy 99.2%，test 98.8%）。
4. **分歧裁决**：5 处全为 NC→其他，逐条重读上下文后裁定 4 处采纳盲标、1 处维持作者标签，
   理由与规则写入 `resolutions.json` / `disagreements.json`。表决与正则标签器均未使用。
5. **独立性边界**：盲标会话与作者是同一模型的不同会话，属于**同源弱监督**，
   不是人工复核、也不是独立人类标注；99% 一致率不能当作标签正确性的证据。

## 4. gold 与封存

- `test.gold.json`：`sha256` 自校验 + 逐条 `{labelId, family}`，仅评测进程读取。
- 预测阶段（特征提取、预测写入、CLI 演示、延迟测量）在 `GoldSeal` 下运行；
  该进程内对 gold 的打开会被拒绝并计数（本轮正向对照：`blocked:GoldBlocked`）。
- `test.inputs.jsonl` 只有 `caseId` 与 `visibleInput`，caseId 为不透明序号，不含标签前缀。

## 5. 已知局限

1. 合成数据，不是真实玩家语料；分布外泛化未证明。
2. 单作者 + 同源盲标，标签正确性只有弱证据。
3. 64 个族是“场景族”，不是真实采集来源；族内仍共享场景设定。
4. 每类在 cal 上只有约 32 条，按族 bootstrap 的区间较宽（见报告）。
5. `test` 的 32 族与 cal 的 32 族仅保证文本/场景不重叠，不保证语义构造完全不相近。
