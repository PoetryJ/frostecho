# 白障风暴细化 · 2026-11-17

本轮保留用户选定的第三版方向：低能见度的冷色雪原、林间的纵深、远处的暖窗。旧版见 [初版截图](previews/storm.jpg)。当前默认进入白障风暴，也仍可切换前两种环境。

## 这次改了什么

- 松树从连续锥形轮廓改为分叉枝条、侧生针叶与枝顶积雪，近处使用 MSAA 覆盖度软化针叶轮廓，远处复用较简单的同类树冠。树与枝顶积雪共用风摆，避免两层错位。
- 屋顶积雪有起伏、厚度和檐口；建筑脚下的积雪形成连续雪堤，保留门口的空隙。小屋增加门廊、木构接缝、紧固件、水平堆放的木柴及风化木纹；玻璃增加霜边与透光不均。
- 取消方块路面，加载时在内存中生成压雪和浅脚印贴图。原村庄道路仍从可通行格网求出；村庄南侧新增的雪地接近路径属于视觉创作，不进入游戏寻路。
- 风雪分成远处细雪、近处顺风雪线、贴地吹雪和烟囱烟；雾密度做缓慢空间变化。没有增加粒子物理模拟，也不将烟或脚印伪装成 NPC 的真实活动记录。
- 远山改为带山脊的高度网格。初始松林机位周围留出空间，避免相机穿进随机树冠后出现近裁剪硬片；小屋近景移到两栋建筑之间的空隙，避免邻屋屋檐挡住主建筑。

## 让细节留在画面里

验收中观察到旧动态分辨率策略将细化后的画面降到约 450×506，抵消了新增细节。因此像素预算现在有清晰度下限：`min(960×720, CSS视口像素数×0.90)`。

达到下限后，先缩短精细树冠距离；强风雪下还可缩短远景装饰距离。时间戳预算仍只是目标，允许实际耗时高于目标，不通过继续降低清晰度来掩盖负载。默认预设不是固定分辨率的性能基准。

新增约 4 MiB 的加载时程序化地面贴图。高细节树冠几何共享并实例化，远处使用简化模型；这些仍增加 GPU 开销，因此不能宣称细化版与初版性能相同。方向光阴影继续采用静态保守近似，尚未精确匹配每根针叶的透明覆盖。

## 验证记录

- JavaScript 语法检查通过；5 项地图/几何检查通过，包含近远树冠复杂度、屋顶起伏、压雪纹理、原建筑/门口坐标、七条通路和生成确定性。
- 已在应用内 WebGPU 浏览器中编译新 shader 并实际查看松林远望、小屋近景和屋内；切换前两种预设后也实际查看了共用材质。最终白障风暴松林视角的图形错误计数为 0，原始地图的建筑足迹没有修改。
- 一次长按 W 600 ms 后，相机从 `(-30, 2.650, 52)` 变到约 `(-28.737, 2.644, 47.868)`；随后长按 E 500 ms，观察到高度约 5.2 m。键盘机位切换和界面隐藏也已实际操作。
- 在 764×857 的 CSS 视口，观察到清晰度下限生效后的 724×812 渲染尺寸。一次松林快照为 GPU 12.255 ms、288 个绘制批次、图形错误 0；后续快照仍有波动。此数字不是平均值或稳定帧率结论。

完整的跨设备性能、长时间画面稳定性和声音主观评价仍未完成。声音图本轮未改动。自由相机仍是场景观察器，允许穿墙；本轮没有接入 NPC/JEV 或权威天气系统。

本轮原生 Edge 窗口处于最小化状态，唤起时被 Windows 拒绝访问，未完成该窗口的新版验收。应用内 WebGPU 预览已保留，可用本地服务在 Edge 中继续查看。
