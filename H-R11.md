## 2. Implemented

| file | role |
|---|---|
| `scripts/r11/run-matrix.mjs` | freeze, phases (`start`/`resume`/two replays), interference, matrix, verify, tamper, D2 report, recompute, exposure |
| `scripts/r11/lib/ids.mjs` | deterministic ids from `seed|uuid-context|occurrence` so a segmented run and a continuous replay mint the same commitment/change ids |

| `scripts/r11/lib/metrics.mjs` | per-instance metrics from the complete decisions/workLog/receipts/memories + resource timeline; hand-checked gap self-test |

Each phase is a separate OS process. `start` saves, writes both pids and the
save manifest; `resume` loads, captures the loaded state and refuses on any
difference (`exit 21`) before playing; the two replays use recorded selections
only (`countsAsModelResult=false`).

## 3. Determinism and the R10 defects this round fixed

1. `randomUUID()` is replaced by a hash of `(seed, uuid-context, occurrence)`.
   Contexts are state-based (`decide:<seed>:<clock>:<version>:<actor>`,
   `delegate:<seed>:<clock>:<origin>:<actor>`, `save:...`), so the resumed
   process and a continuous replay produce identical ids.
2. The R10 night-skip arithmetic turned a 04:00 wake into **next day 06:00**,
   which skipped the whole D2 morning. The R11 runner wakes at the next 06:00;
   with the old code the reference saved at D2 12:00 with **0 bound intents**
   exactly because of that skip.
3. R10's reference arm force-withdrew every promise when merely tired/hungry
   (`hunger<45 || stamina<35 || bodyTemp<35.9`), consuming the interference
   before it could be measured. That runner-side rule is removed; the reference
   now chooses from the same candidate set (the bridge still offers
   `withdraw-commitment` at real survival extremes).

## 5. Four stories: offered vs taken

Probe (`probe-bridge-first`, control only) takes the first bridge candidate and
proves the scenario offers all four stories on both seeds:

| story | r11h-1 | r11h-2 |
|---|---|---|
| heard cancel while work in flight | 1 instance (intent cancelled at 2050) | same |
| unheard cancel + relay at +30 | 1 instance; post-cancel attempt rejected, **0 receipts** | same |
| source change proposed after a real `out_of_stock`, explicitly refused | 1 (`rejected`, revision stays 1, **0 unagreed-source actions**) | 1 |
| old failure lifted by a witnessed restock | restock +2 at 2100 (observed by the residents at the warehouse), the losing promise witnesses it and then fulfils | same |
| two commitments contend for the last unit | one withdraws the last unit (`remaining 0`), one `out_of_stock` then recovers after the restock | same |

Reference arm (rule policy, no model): both cancels and the two contention
targets are offered; it makes **1 rejected post-cancel attempt and 0 late
receipts**. It does **not** reach the source-change/restock story: its
`referenceUtilityWithGoals` drops the obligation bonus under `immediateNeed`
while task-bound base candidates keep theirs, so it keeps moving instead of
withdrawing. This is recorded as `not_exposed`/null, not as a zero violation,
and is a concrete policy defect for O (§8).

## 8. Findings for O

1. **Reference policy defect**: under `immediateNeed` the bridge candidates lose
   the `+0.25` obligation bonus (only `taskBindingOfCandidate` candidates keep
   it), so the rule reference wanders instead of withdrawing/acting. If R11
   needs the reference to exercise the change/restock stories, either the bridge
   candidate must carry `taskId/taskType`, or the reference's tie-break must be
   made explicit and named. I did not change the shared reference/bridge code.
2. **D2 ordering is fixed**: R10 interfered before saving; R11 saves with bound
   work first, then the new pid resumes, then every story fires at/after its
   frozen trigger.
3. **Full-state restore is achievable** with one determinism control
   (deterministic ids) and the state-based contexts; the comparator detects all
   five corruptions on both the save and the final state.
4. **Live matrix remains blocked on C + GPU**, not on the harness.
